## 1. 已确认的研究主线

> 建立双主体偏好感知的教学方法分配模型，以精确求解验证其权衡关系与最优水平，再研究共享 PPO 在多偏好场景中的近似求解质量和批量服务效率。

研究价值分成两层：模型是否合理表达教学效果与双主体偏好的权衡；共享 PPO 是否能在该模型下提供有竞争力的近似质量和多场景服务效率。

已确认的边界：

1. 希望保留 PPO 作为主要研究方法，但不得预设 PPO 必须优于所有基线，也不得据 PPO 表现反向挑选有利的目标权重。
2. 不再采用“先保证教学效果，再优化偏好”的叙事。教学效果可以为偏好让步，暂不设置 F_E 下限。
3. 学生与教师保持等权重；偏好变化及对新内容、新偏好的适应是重点。
4. 部署目标为覆盖全部纳入规模的一个共享模型，不按每个实例或每次偏好变化重新训练。
5. 固定方法—类别教学效果矩阵；合成偏好场景采用有教学含义的 6 类学生模板 × 6 类教师模板及连续扰动。它们是合成设定，不是已被真实教学数据验证的效用模型。
6. 主实验先固定一套权重；权重变化作为后续敏感性实验，不默认把权重条件化加入模型。

需验证而非直接宣称：PPO 是否真正利用偏好输入、面对偏好变化是否接近精确解、批量请求下是否获得质量匹配的吞吐优势、动态调整是否具有额外收益。

## 2. 数据范围与重新训练

### 已确认

- 新版训练、validation 和正式测试排除 staircase，保留 uniform、random、hourglass、bottleneck。
- 原始五类拓扑数据在 `pre_data`。staircase 原始数据及既有实验结果不删除、不覆盖，作为历史探索记录保留。
- 用户认为 staircase 的结构及内容构成不符合目标应用场景，接受为调整研究范围重新训练。
- 新版主模型需要覆盖纳入拓扑的全规模内容，并学习不同偏好场景。

### 必须补充的论证与审计

1. 排除理由需从内容类别组成、认知需求和目标课程适用范围出发，形成与算法成绩无关的可检查描述。不能写成“staircase 普遍不合法”或仅以 PPO 分数低为理由。
2. 当前分配模型不直接使用拓扑边；拓扑主要通过上游选择结果的内容组成影响分配任务。不能宣称 PPO 已学习显式拓扑推理。
3. staircase 与固定目标分布存在张力是既有分析线索，不是一般性不可解结论；弱化全局项可能缓解张力。范围调整须如实披露为探索后决定。
4. 新划分按底层内容实例分组隔离，保留原始实例 ID、拓扑、规模、scenario ID 和种子；同源变体不能跨训练与独立内容测试泄漏。
5. **旧 interpolation / held-out 测试已经运行且结果已用于讨论。** 不得把旧测试重新命名后称为未查看的独立确认集。只生成新偏好也不能自动获得“新内容”测试。

### 待确定与处理方案

- 先审计可用内容及历史访问范围，再确定新 train / validation / 独立确认集的比例、数量和来源。
- 如果缺少真正未使用的新内容，应向用户说明并请求新增数据或明确接受探索性评估；不得隐藏限制。
- 主张的泛化范围为四类已知拓扑中的“新内容 + 新偏好”；是否另设未见画像组合或超出训练扰动范围的偏好测试，应单独定义。不要将其混称为未见拓扑泛化。

## 3. 目标函数：已确认方向与待冻结参数

### 当前实现，仅作历史参照

`J_old = 0.30 F_E + 0.25 F_S + 0.25 F_T + 0.10 F_G - 0.10 V_soft`

其中 `F_G = 1 - 0.5 * L1(pi, rho)`；`pi` 为方法使用比例。当前软惩罚形式为：

`V_soft = lambda_div * max(0, H_min - H(pi))^2 + lambda_cap * sum_m max(0, pi_m - cap)^2`

历史配置：`H_min=0.55`、`cap=0.35`、两个内部 lambda 均为 1；外部惩罚系数为 0.10。当前非均匀参考分布为：

`rho = [0.18, 0.12, 0.10, 0.10, 0.10, 0.08, 0.08, 0.08, 0.05, 0.05, 0.06]`

上述数字未因本次讨论自动变更。当前实际权重以 `pa_moap_rl/configs/profile_config.yaml` 为准，旧 `model_definition.md` 中的数字需后续同步审计。

### 已确认的语义

- 教学效果与双主体偏好允许补偿性权衡，学生与教师等权。
- 用户更倾向于把全局项作为避免教学方法过于单一的辅助引导，而不是强制匹配某个比例。
- V_soft 的惩罚系数应单独校准。
- 接受非均匀方法分布，但不将当前合成 rho 声称为真实学校规则或经过教学实证的最佳比例。

### 建议表达，尚待确认

令 `F_P=(F_S+F_T)/2`：

`J = alpha_E F_E + alpha_P F_P + alpha_G F_G - lambda_soft V_soft`

建议正向系数满足 `alpha_E + alpha_P + alpha_G = 1`，惩罚系数单独设置。用户此前“其他项系数为 1”的表述仍需澄清：是指各正向系数均为 1，还是正向系数之和为 1；不能擅自认定。

以下只是讨论候选，不是新配置：

| 方案 | F_E | F_S | F_T | F_G | 用途 |
|---|---:|---:|---:|---:|---|
| 原模型等比例归一化 | 1/3 | 5/18 | 5/18 | 1/9 | 历史参照；要完整等价，外部惩罚也需变为 1/9 |
| 建议起点 | 0.35 | 0.30 | 0.30 | 0.05 | 偏好为主体，保留效果与弱全局引导 |
| 偏好强调 | 0.30 | 0.325 | 0.325 | 0.05 | 检查进一步偏好倾斜的代价 |

完整目标乘同一个正数不会改变精确最优解排序，但会改变 RL 奖励尺度，不能直接认定训练等价。不同权重下的 J 不可直接用于证明算法进步，应同时报告原始分项。

### 全局项分工与待决定问题

- F_G：偏向一个参考方法组合；它并不等价于一般性的“避免单一”。
- 熵不足惩罚：约束整体多样性不足的程度。
- 方法占比惩罚：抑制某一种方法过度集中。

建议保留低权重 F_G 作为软参考，同时检查与熵/占比惩罚的重复作用；如果最终需求仅是防止单一，也应评估去掉 F_G 的模型方案。F_G 是否保留、rho 是否固定、熵阈值和占比阈值是否沿用，均须冻结后再做新版正式训练。

### 校准处理方案

1. 在新范围内的开发/validation 样本上，先用精确/有界解比较候选目标的分项权衡，区分模型偏好与 PPO 优化误差。
2. 扫描惩罚系数，记录实际熵、最大方法占比、违反程度及教学效果/双方偏好损失。扫描网格、样本量和决策准则先给用户确认。
3. 不只观察系数大小，要观察各项实际可变范围及对最优分配的贡献。平方惩罚数值可能很小，不能凭系数 0.1/1 判断强弱。
4. 以研究目标与可解释的分项代价确定方案；没有真实业务阈值时，明确属于建模选择及敏感性分析，不伪称教学显著性。
5. 实施前统一完整评分、环境增量评分、greedy/局部搜索、Gurobi、结果重算及 checkpoint 中的配置来源，并补一致性测试。

## 4. 四个实验方案与依赖关系

已确认顺序：方案 1、2 可同步推进；方案 3 是效率贡献的重点；方案 4 后置、作为可选补充。这里的“同步”指工作安排，不代表已授权在单 GPU 并发多训练。

| 方案 | 要回答的问题 | 处理方案与关键输出 |
|---|---|---|
| 1. 双主体偏好响应 | 解是否随真实偏好合理调整，PPO 是否确实利用偏好？ | 同内容下分别改变学生、教师、双方偏好，设置一致/冲突画像；比较精确解、greedy、局部搜索、PPO。报告 F_E/F_S/F_T/F_G/V_soft、旧解在新偏好下的损失及重求解增益。 |
| 2. 搜索预算与质量 | 128 步是否限制大规模质量，增加预算是否有效？ | 先做固定 checkpoint 的 128/256/512 步及随 N 缩放的诊断，单独控制 patience；记录 best-so-far J、单点替换次数/覆盖节点、anytime 曲线和等时限 gap。步数仅是建议诊断档位。 |
| 3. 批量服务效率 | 多偏好请求下，共享 PPO 是否能摊薄成本？ | 同内容多偏好、新内容加新偏好两类负载；建议 batch=1/8/32/128，按 N 分桶/padding。报告质量匹配下吞吐、平均/P95 时延、资源及训练摊销。批量推理不等于训练时 joint B=4。 |
| 4. 动态偏好调整 | 利用旧方案能否改善后续求解？ | 小幅漂移/突变；比较旧解不动、PPO 重启/旧解启动、局部搜索旧解启动、Gurobi 模型复用与 warm start。变更节点数仅作描述，除非另行确认加入切换成本。 |

补充边界：

- 方案 1 中均值/错误偏好输入可以作为已训练 PPO 的诊断，所有输出必须按真实偏好评分；不能冒充从头训练的“无偏好输入”消融。
- 最优解可能不唯一，分配变化多不代表偏好处理更好；精确最优分配不变时，也不能仅凭 PPO 输出不变判其失效。
- 128 个单点动作最多触及 128 个不同节点，重复动作和提前停止会进一步减少覆盖；这只是大 N 的潜在瓶颈，不是已验证原因。延长评估可能偏离训练分布，不保证改善。
- Gurobi 也能直接处理新偏好系数、复用模型或热启动，不能把“支持偏好变化”说成 PPO 独有优势。
- 方案 3 必须给 Gurobi 合理的线程/并发配置，并比较早停 incumbent，而不只比较完整最优性证明时间。
- 方案 4 的旧解初始状态可能不符合当前 effect-only greedy 训练分布，需要诊断，必要时另行设计训练。

## 5. 质量、对比与时间口径

目前没有业务/教学方面已给定的可接受质量阈值。建议报告相对最优 gap 的 1%/2%/3%/5% 分档达标率，以及均值、中位数、P90、最差值；这些是计算评价档位，不是已确认教学标准，也不是冻结门槛。

- 已证最优时，报告绝对差 `J* - J_alg` 和相对差 `(J* - J_alg)/max(abs(J*), eps)`；说明分母定义。
- 未证最优时，报告 incumbent 下界和全局上界，以及算法解到上界的有界差距；不把未知 J* 当成已知。
- 固定配对内容与 scenario，对分项、拓扑、规模、画像冲突程度分层汇总。统计差异与真实教学意义分开讨论。
- 基线包括随机可行、Effect-only greedy、标量 greedy、现有单点 best-improvement local search、Gurobi、PPO；PPO+短程局部搜索保留为待验证混合方案。
- 局部搜索只是规范改名，不新增一套重复算法，不称“全局局部搜索”，也不是全局最优上界。全局上界来自精确求解器。
- 不增加人为禁用关系来制造 mask 优势；保留原建模能力，当前全部可行的应用场景下，相关消融解释力有限。
- 统一端到端计时，覆盖必要初始化、初解、数据传输和求解；模型加载/一次性建模成本及缓存复用另列，分别报告冷启动与稳态口径。GPU 计时需正确同步。
- 保留 CPU/GPU 型号、线程数、batch、并发、预算、热启动来源、重复次数和统计口径；不沿用尚未统一的历史耗时直接宣称最终加速比。

## 6. 工程、复现与新版训练

1. 新数据、目标版本和结果目录独立命名；保留全部旧 checkpoint、日志、测试和图件。不要覆盖旧 seed0 或旧数据集。
2. 保存代码版本/差异、完整有效配置、数据及 scenario 标识/哈希、随机种子、设备、时间、checkpoint 来源和恢复链。
3. 继续输出 TensorBoard、逐 update/逐实例 CSV 或 JSONL、固定 validation 分项及分层结果、最终 assignment、best/latest checkpoint。
4. 训练监控至少包括 validation J 与各分项、gap（在有精确参考的固定子集上）、标准化策略熵、KL、clip fraction、可行性、非法动作、吞吐、显存和耗时。策略熵与方案方法分布熵必须分开命名。
5. 历史超参数可作为新版 seed0 pilot 起点，但不能把旧的参数冻结、1500 updates 或绝对分数门禁直接移植到新目标。
6. 先验证目标/数据/恢复一致性，再做短程 pilot，随后决定是否调整搜索预算与超参数；候选稳定后进行三种子正式训练。
7. 正式 PPO 消融后置；已有启发式目标项消融脚本不能代替从头训练的 PPO 消融。
8. 用户曾希望 9 月 18 日前有初步可展示结果；应按剩余时间优先做可解释的目标校准、seed0 和核心比较，重排预算并明确哪些只能是探索性结果，不保证未验证的日程。

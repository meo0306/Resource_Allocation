# 四拓扑批量服务效率实验协议 v1

本实验只使用已经冻结的 Stage6 主线：`legacy_separate_v1`、run03 update60、b075 目标以及确定性 512/32 推理。6A 的 A/B/C/D/E 模型和损失不进入本实验。

## 要回答的问题

1. 同一内容对应多组偏好时，共享策略能否通过真正的模型 batch 摊薄前向成本？
2. 内容与偏好同时变化时，按 N 分桶和 padding 后是否仍有吞吐优势？
3. 在 mean gap 与 P90 gap 同时匹配的条件下，PPO 与 greedy、局部搜索和 Gurobi 的吞吐与时延关系如何？

## 实现口径

`batched_policy_service_v1` 为独立推理引擎。每个请求拥有独立环境、patience、best-so-far 和完成时间；请求完成后从活动 batch 中移除，不重置。计时前后同步 CUDA，同时记录环境 reset、模型前向、环境评分更新和结果重算时间。batch=128 失败时直接记录 OOM，不进行未声明的微批处理。

正式测试 batch=1/8/32/128，覆盖“同内容多偏好”和“新内容加新偏好”。主结果按 N 分桶，另报告混合 N padding 压力。冷启动、首批和稳态分开，训练耗时不计入在线时延，只单列摊销。

## 质量匹配

从已有 b075 精确结果覆盖的 controlled-cross 中确定性选择36个拓扑×规模分层请求。PPO 测试128/32和冻结的512/32；局部搜索扫描4/16/64轮；Gurobi扫描0.25/1/5秒、单请求单线程。只有 mean gap 和 P90 gap 均达到 PPO 水平的配置才称质量匹配；否则只报告质量—时间非支配前沿，不生成强制加速比。

## 门禁与停止

- batch=1 与批量结果的 assignment、停止原因和步数必须一致，评分误差不超过 `1e-9`。
- 所有结果必须硬可行、无 mask violation，目标、方法矩阵、数据和 checkpoint 哈希必须吻合。
- 任一正确性门禁失败即停止正式计时。
- 实验不训练、不修改冻结目标、不修改 checkpoint，也不把开发数据称为独立测试。
